# yml2csv

Конвертер [Yandex YML](https://yandex.ru/support/marketplace/ru/assortment/auto/yml) в CSV.
Один и тот же код разбирает фид для командной строки и для страницы на GitHub Pages.
Подходит для выгрузок Яндекс Маркета, Яндекс Директа и маркетплейсов, которые принимают YML.

XML читается потоковым SAX-парсером ([saxes](https://github.com/lddubeau/saxes)), без сборки всего документа в дерево.
Поэтому фид на сотни мегабайт не обязан помещаться в память целиком. На входе — UTF-8 и windows-1251.
На выходе — CSV по [RFC 4180](https://www.rfc-editor.org/rfc/rfc4180): кавычки удваиваются, перевод строки внутри поля не рвёт строку.
Для русского Excel есть режим с разделителем `;` и UTF-8 BOM.

## Командная строка

Нужен [Bun](https://bun.sh). Из клона репозитория:

```bash
bun install
bun src/cli.ts examples/shop.xml > out.csv
bun src/cli.ts examples/shop.xml --excel -o shop.csv
bun src/cli.ts examples/shop.xml -c id,name,price,category
bun src/cli.ts - < examples/shop.xml > out.csv
```

После публикации пакета в npm те же команды доступны без клона. Файл фида — свой, локальный:

```bash
bunx yml2csv feed.xml > out.csv
bunx yml2csv feed.xml --excel -o out.csv
bunx yml2csv feed.xml -e windows-1251 -c id,name,price,category
```

| Флаг | Что делает |
| --- | --- |
| `-o, --output` | Файл результата. Без флага CSV идёт на stdout |
| `-d, --delimiter` | Разделитель полей: `,`, `;` или `tab` |
| `--excel` | То же, что `-d ';' --bom` |
| `--bom` / `--no-bom` | UTF-8 BOM в начале файла |
| `-e, --encoding` | `auto` (по умолчанию), `utf-8`, `windows-1251` |
| `-c, --columns` | Какие колонки вывести и в каком порядке |
| `-q, --quiet` | Не писать сводку в stderr |

`auto` смотрит на BOM и атрибут `encoding` в XML-декларации. UTF-16 не поддерживается.

## Страница

```bash
bun install
bun run dev
```

Откроется `http://127.0.0.1:5173`. Можно перетащить файл, вставить ссылку, включить режим Excel, выбрать колонки и посмотреть первые строки перед скачиванием. Конвертация идёт в браузере.

Ссылка на фид сработает только если сервер отдаёт заголовок CORS. Иначе сохраните файл и откройте его с диска: у старой версии для этого был отдельный прокси, теперь его нет.

Прод-сборка: `bun run build`. Статика попадает в `web/dist`. GitHub Actions выкладывает её на GitHub Pages (домен из `web/public/CNAME`). В настройках репозитория источник Pages должен быть **GitHub Actions**.

## Что попадает в CSV

Каждый `<offer>` — строка.

- Атрибуты оффера (`id`, `type`, `available`, `group_id` и другие) становятся колонками.
- Обычные элементы (`price`, `name`, `vendor`, `author`, `ISBN`, поля туров и билетов и остальные) тоже становятся колонками. Тип оффера — `vendor.model`, упрощённый, `book`, `audiobook`, `artist.title`, `tour`, `event-ticket` — не отбрасывается: берутся те поля, которые есть в фиде.
- Несколько `picture`, `barcode`, `date`, `collectionId` склеиваются через `|`.
- `<param name="Цвет">` попадает в колонку `param:Цвет`. Если указан `unit`, колонка называется `param:Память [ГБ]`.
- `categoryId` дополняется колонкой `category` с путём по `parentId`: `Электроника > Телефоны > Смартфоны`.
- Доставка, самовывоз, точки и состояние сжимаются в `delivery_options`, `pickup_options`, `outlets`, `condition`, `condition_quality`, `condition_reason`.
- `<price from="true">` даёт цену и колонку `price_from`.

Порядок колонок стабильный: сначала поля спецификации, затем незнакомые теги в порядке появления, в конце `param:*`. `--columns` заменяет этот порядок на свой.

## Отличия от конвертера 2017 года

Старая страница забирала YML через прокси, разбирала его jQuery в одно большое дерево и выкидывала из оффера всё, что не было простой строкой. Сверка на том же примере фида:

| | Версия 2017 | Сейчас |
| --- | --- | --- |
| Категория | Только лист: `Смартфоны` | Путь: `Электроника > Телефоны > Смартфоны` |
| Атрибуты | Колонки `@id`, `@available`, `@type` | `id`, `available`, `type` |
| Несколько `picture`, `barcode`, любой `<param>` | Поле пропадало: массив и объект удалялись | Сохраняются |
| `<price from="true">` | Цена пропадала, потому что элемент становился объектом | Цена и `price_from` |
| Колонки | Только ключи первого оффера, остальные терялись | Объединение по всему фиду |
| Один `<offer>` в фиде | Цикл шёл по полям объекта, CSV был мусором | Одна нормальная строка |
| Кавычки и перевод строки в описании | Строка всегда в кавычках, внутренние `"` не удваивались, строка CSV ломалась | RFC 4180 |
| Конец строки | `\n` | `\r\n` |
| Excel | Всегда запятая, без BOM | `--excel` или галочки на странице: `;` и BOM |
| Кодировка | Как отдал браузер | UTF-8 и windows-1251 |
| Память | Весь XML как DOM | Потоковый разбор в два прохода |

Там, где старый код оставлял простое текстовое поле, значение совпадает: цена, название, url, валюта, лист категории для корневого раздела.

## Разработка

```bash
bun install
bun test
bun run typecheck
bun run build
```

Стек: Bun, TypeScript, Vite. Единственная runtime-зависимость — `saxes`.
Ядро — `src/`, CLI — `src/cli.ts`, страница — `web/`.
В npm уходят `dist/` и этот README (`files`, `bin`, `exports` в `package.json`).

## Выпуск версии

Версия живёт в `package.json`. Тег должен с ней совпадать: для `2.0.0` это `v2.0.0`.

```bash
# version в package.json уже обновлён и закоммичен в master
git tag v2.0.0
git push origin v2.0.0
```

Тот же тег создаёт GitHub Release. Workflow `.github/workflows/publish.yml` прогоняет тесты, собирает пакет на Bun и выполняет `npm publish --provenance --access public`.

Первый выпуск требует секрет `NPM_TOKEN`: пакет ещё не существует, и trusted publisher на npmjs.com включить некуда. После появления `yml2csv` в реестре публикацию можно перевести на Trusted Publishing и секрет удалить.
